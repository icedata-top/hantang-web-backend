# PostgreSQL 建表语句与表文档约定

适用范围：本项目交付给开发者手动执行的 PostgreSQL DDL，以及表结构文档。

## 建表语句格式

- 交付给开发者直接执行的建表 SQL 不要空行，避免 SQL 工具按空行分段执行。
- 仓库 `sql/` 中作为文档保存的 SQL 面向开发者和 AI Agent 阅读，可以使用空行、分组注释和字段说明；它不等同于直接执行版。交付直接执行版时再移除空行并提示完整选中执行。
- 每条语句必须完整，以分号结束；不能交付只有字段片段、缺少右括号或包含省略号的可执行版本。
- 直接执行版的说明文字优先放在 SQL 代码块外；文档版可使用 SQL 注释，字段说明也可使用独立的 `COMMENT ON` 语句。
- 明确提示完整选中整条 `CREATE TABLE ... );` 执行，不要只执行到字段末尾的逗号。
- 不默认添加 `DROP TABLE` 或用 `IF NOT EXISTS` 掩盖已有同名表的结构差异。

## Schema 与命名

- 使用现有 schema `hantang_dynamic`，表名、索引目标、注释和查询示例使用一致的限定名称。
- 不创建 `adm` schema，不输出 `CREATE SCHEMA IF NOT EXISTS adm;`。
- ADM 聚合表用 `adm_` 前缀标识，例如 `hantang_dynamic.adm_entity_metrics_daily`。
- 区分数据库与 schema：仓库字段快照记载的数据库为 `hantang`，schema 为 `hantang_dynamic`；未经线上检查，不声称所有数据库对象都在此 schema。

## 表文档位置

- 表结构文档和配套 DDL 统一放在仓库根目录 `/sql` 下，即本项目的 `sql/`，不是操作系统根目录。
- DDL 使用 `.sql`；可直接在其中通过注释记录表说明，必要时补充同名或对应名称的 `.md`。草案文件明确标注草案状态。
- 表说明至少记录用途、完整表名、行粒度、字段含义、主键/索引、统计时间口径及 NULL/缺失值语义。
- `doc/design` 可保留方案讨论与评估，但具体表文档落入 `sql/`，通过链接引用，避免维护互相矛盾的结构定义。
- 结构或命名变化时，同步更新 DDL、表说明和相关查询示例。

## 手动执行与错误定位

- 交付 SQL 不代表已执行建表；用户手动执行时，不擅自连接数据库或执行 DDL。
- `current transaction is aborted` 表示此前已有语句失败，应先定位最初错误；需要恢复连接事务状态时，单独提供 `ROLLBACK;`，并说明它会撤销当前未提交事务。
- 不在普通建表脚本开头默认嵌入 `ROLLBACK;`，以免撤销开发者其他未提交操作。
- `syntax error at end of input` 应检查是否仅执行了部分建表语句、缺少右括号或语句被工具分段；不能仅凭此错误认定表设计有问题。
- 建表、索引和注释均需完整执行；手动提交模式下提醒提交，不能把编辑器中的执行提示当作已提交成功的证明。
