# UniSeek：迁移 Elasticsearch 并建立正式排序与分页

状态：待实施。Beta 实现见 [接口及排序说明](../../frontend/src/services/UniSeek/uniseek.md)、[UniSeekDao](../../src/main/java/com/hantang/web/dao/UniSeekDao.java)。

Beta 对关键词歌曲结果做 60 秒、最多 16 个关键词的有界内存缓存，降低无限滚动的重复查询开销；热门二字词未缓存首查实测仍约 3–4 秒，后续需继续降低冷查询延迟。当前使用 PostgreSQL 标题 trigram、现有标签/分词/歌手数组索引召回，最多 1,000 首候选歌曲参与评分。精确 AV/BV、文本匹配档位、长度接近度和有上限的对数播放量构成临时排序；歌手在前端本地匹配，视频/UP 主关键词和精确编号请求独立并发，结果按到达顺序追加，后续只分页加载歌曲；不再做后端跨类型评分排序。这是有限候选的 beta 方案，短词及拼写错误召回能力有限，并非全量相似度搜索。

后续应建立 processed_videos、discovered_users 与歌手配置的 Elasticsearch 增量同步及删除处理，评估中文分词、别名、繁简体、拼音、错别字和歌曲名提取；以真实搜索样本比较相关性、播放量、时效性，确定可解释的正式评分函数与离线评测集，并建立便于检索的每视频最新指标快照，替代 beta 全库最新有数据日统一快照（日期缓存 10 分钟）的临时口径。

使用 PIT + search_after 或等价快照游标，消除 PostgreSQL 页码分页时新增视频/播放快照更新造成的跨页漂移；取消 1,000 候选上限。确认视频收录/过滤状态、创作者统计口径及空值规则后再调整搜索范围，不凭 is_filtered 字段名推断业务语义。

验收应包含中文短词、长歌名、歌手/创作者同名、精确编号、纯数字歌名、同分稳定顺序、连续翻页及并发查询的 P50/P95 延迟，记录不同量级热门词的执行计划和候选召回率。
