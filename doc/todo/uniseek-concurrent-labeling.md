# UniSeek：并发标记与下载任务式进度面板

创建：2026-11-19。更新：2026-11-20。状态：1000条范围的并发执行、进度指标和结束总结已实现；续跑、失败补跑及20万条容量验证待实施。仅用本机模拟接口验证，没有发起真实Qwen运行。

## 问题与期望

原[Java任务](../../src/main/java/com/hantang/web/task/VideoTypeAndLanguageAnalysisTask.java)逐批同步请求，1000条实测耗时564.347秒，线性估算20万条约31.35小时。本次仍固定从头处理1000条、每批20条，不实现失败补跑；已改为并发HTTP、单一写入端及分批结果落盘。20万条规模暂不处理。

期望在已有复核页的Qwen执行卡片中，由用户选择并发数，受控并发处理多个批次。进度参考面向普通用户的下载任务，常用信息直接可见，保留条形进度条，不增加速度趋势图；请求失败可追溯，结果持续保存，已成功视频可以复用。

完整设计、指标定义、限流与预算依据统一见[并发执行与容量估算](../design/uniseek/qwen-batch-execution.md)，界面基础规范见[复核页说明](../design/video-label-review.md)。以下默认值和容量数字不代表实测承诺。

## 已确认需求

- [x] 前端在启动前选择并发数，后端校验并保存实际配置，刷新后恢复；并发作用于任务内部批次，而非同时新建多个完整任务。
- [x] 保留现有条形进度条及成功/失败计数，新增活跃线程/上限、单次API平均耗时、每分钟处理视频数、剩余视频数、已用时间、预计剩余时间、预计完成时间。
- [x] 主信息紧凑常显，token、TPM、重试和错误详情可展开；窄屏可换行、日夜主题可读，不引入速度趋势图。
- [x] 指标根据后端真实事件和持久化进度计算：重试不重复计数、最终失败与成功分开；估算尚不可用或数据过期时明确显示未知，不伪造速度和倒计时。
- [x] 执行结束后常显成功/最终失败、实际耗时与完成时间、平均速度、API平均耗时、请求/重试次数和已知token；展示歌曲、虚拟歌手歌曲、含汉语虚拟歌手歌曲及不确定条目数，明确为模型判断而非准确率。

## 实施拆分

- [x] 建立有界批次调度和共享限速预算，保留最多2次重试。等待退避的批次释放HTTP名额，其他批次可以继续；处理429、503、超时和模型输出校验错误。
- [x] 单一写入端维护状态，分批持久化结果与尝试原文；结果落盘后推进进度，结束后按输入顺序写出v1 JSON，不再逐请求重写累计结果。
- [ ] 为大规模任务改为全程增量统计和有界内存合并；当前1000条仍在内存保留结果，并在事件发生时汇总最多50批的运行日志，未做20万条验收。
- [ ] 实现继续任务及失败补跑；启动前明确目标范围、本次需调用数、已保留成功数，按模型/提示词/输入版本校验复用条件。补跑用量与历史用量分别统计。
- [x] 扩展状态接口和运行统计，统一计数、活跃请求、API耗时、近期速度、TPM/RPM和ETA口径，快照包含更新时间；请求平均耗时按已结束尝试汇总，速度按窗口内唯一视频完成数计算。
- [x] 前端使用现有Ant Design控件和主题样式，配置启动时固定；保留结果、统计下载入口，支持大文件直接下载，轮询不搬运20万条数据。
- [x] 保存任务参数及来源摘要，确保刷新或重启不丢已落盘结果。人工标注、Qwen历史结果及prompt保持独立，错误日志继续脱敏。

## 候选参数与预算记录

每批20条。前端提供1/4/8/16/32/64、默认8，启动后固定；32—64尚无真实Qwen吞吐验证。所有工作线程共享本次执行预算：可通过`llm.execution_tpm`、`llm.execution_rpm`配置，默认100万TPM、600RPM是本地保守执行上限，不代表平台额度。先预留估算用量，返回后校正，未知用量保留预留值；请求至少间隔100ms。

串行实测平均总TPM约4.49万。按用户引用的500万TPM档位计算，32并发约144万TPM、64并发约287万TPM；20万条理想耗时分别约59分钟和29分钟。具体以实际地域/账号限额及运行指标为准，不自动发起并发试跑。

全量20万条预计约8,449万token，按此前用户提供的单价估算约¥89.65，基线已包含实测重试摊销，未计缓存优惠。输入长度、错误率等变化会改变预算；实际完成时间及费用尚未测得。详细算式和官方限流来源只维护在设计文档中。
