# Web 数据缺失识别与展示

状态：部分实施，本文为讨论及改造草稿，不是最终PRD。创建日期：2026-10-26，更新日期：2026-10-27。

## 需求背景

2026-10-27用户确认：当前已知的一项数据缺失问题发生在MySQL向PostgreSQL同步的环节，属于另一Git仓库及其owner负责的待修复问题。该同步问题及复核证据统一记录在[MySQL到PostgreSQL同步数据缺失](mysql-postgresql-sync-data-loss.md)。具体漏同步机制与修复进度由外部owner确认。

用户提供的最新PostgreSQL查询截图显示，`hantang_dynamic.video_daily`在2026-10-21、26、27日的记录数为0；25日已有609841条，更新此前“25日无记录”的观察。27日为查询当日，记录数仅代表截图时点状态。数据库缺少记录不代表视频播放量等业务指标为0。

Web需要如实呈现可用数据，避免把源缺失显示为0或剧烈业务变化。数据写入日志时间、record_date和真实观测时间不是同一个概念，跨日结束的任务不能由Web自行改写归日。

本待办记录规则与实施顺序；中术50趋势的缺失值传递和折线断点已完成，其余事项按下列清单推进。

## 职责与外部依赖

- 本项目负责查询后端及前端：识别快照完整性、保留NULL与日期、计算可用指标并如实展示缺口；同步补数后验证查询结果恢复。
- 数据爬取、MySQL到PostgreSQL的数据同步及上游数据预处理不属于本项目实施范围。同步缺失的根因修复、历史补数及同步链路验证由另一仓库的owner负责，不在本仓库新增替代同步任务。
- 本项目的缺失展示修复已完成部分内容，但不表示上游同步问题已解决；上游修复及补数状态与Web展示改造分别跟踪。

## 当前代码已有能力与缺口

- 指标卡：`OverviewDao.sumViewAndFavoriteForRecordDate`对中术50播放、收藏分别检查样本与非空字段；`OverviewService.difference/nullableRatio`保留NULL，`IndicatorCell`显示“暂缺”。这部分应保留，真实0仍显示0。
- 趋势后端：`OverviewDao.queryZhongshu50DailySnapshots`仍查询明细表，逐指标检查50个样本及非空字段；`OverviewService.buildVideoStatsTrend`仅对相邻自然日的完整快照作差，缺D或D+1时返回NULL，真实0和负增量保留。
- 趋势序列化：中术50趋势保留请求区间的每个日期及全部指标键，缺失值明确返回NULL；缺失原因等元数据仍待扩展。
- 趋势前端：`OverviewTrendChart`保留中术50的NULL和日期，缺口断线、不补0。投稿趋势合并仍有补0逻辑；后续需结合其源数据可用性区分已确认无事件和源缺失，不一概替换所有计数0。
- 筛选默认按昨天为结束日，没有使用真实数据可用状态。查询日期合法不代表该日快照齐备。
- 当前Web查询尚未接入新ADM表。ADM任务succeeded不代表所有指标is_complete=true，不能仅凭任务状态显示“数据完整”。

## 优先规则

1. **0与缺失分开**：已确认完整集合上的0显示0；缺失显示“暂缺”；请求失败显示加载失败，不能变成空数据。能够判断采集/同步尚未完成时再显示“待更新”，不能仅凭NULL猜原因。
2. **日趋势按指标断开**：D或D+1任一必要快照缺失/不完整，该指标D日增量为NULL，不补零、不跨缺口连线、不插值。其他有完整数据的指标仍可展示。
3. **比较条件独立校验**：当期值可用但上期缺失时保留当期值，环比显示暂缺；基数为0时显示“无法计算”或相应说明，不显示无意义百分比。
4. **说明缺口**：提示所选范围有数据暂缺，允许展开具体日期、指标及已知原因。提示停留在受影响模块，不因为daily缺失就屏蔽独立来源的新投稿等全部内容。
5. **展示真实可用范围**：区分最新有快照日期、最新可计算完整业务日及区间内部缺口，不仅取MAX日期就认定历史完整。

范围统计要按实际算法解释：固定样本集合的期初、期末均完整时，端点相减仍可计算整个区间增长，即使中间某天快照缺失；但该日趋势仍缺失。若接口改为SUM日增量，则需检查所有日覆盖，不能让SUM跳过NULL后冒充完整区间。成员变化时还需统一集合口径，不能混用两种算法。

负增量本身不能直接视为缺失，源端可能发生修正；先通过快照完整性判断是否可计算，不能把所有负数截为0。

## 候选接口信息

按模块/数据范围提供状态和简要元数据，字段名待确定：数据完整、部分缺失、无可用数据；缺失日期及指标；最新有效快照日期；最近聚合时间。源原因未知时只报告缺失，不推断“服务器采集失败”。

日期级有行数不证明每个对象和指标完整。全量、分区和中术50的完整性按各自集合检查；每日行数允许正常变化，不能要求每一天行数相等。

已有ADM覆盖计数、指标NULL及is_complete可用于后续页面，但两个计数是七项指标整体覆盖，不是单项覆盖率。computed_at是聚合时间，不是源观测时间；没有实际观测时间字段时，展示快照日期即可，不编造精确观测时点。
