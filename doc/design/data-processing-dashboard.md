# 数据中心：数据处理看板

入口：`/admin/data/processing`，沿用管理入口开关。只读展示处理结果、业务任务和调度情况，不建表、不执行任务、不改变 CRON 或数据库权限。

## 卡片与处理范围

- **UniSeek 搜索集发布**：读取 `hantang_dynamic.adm_uniseek_videos` 的当前批次，展示精确行数、来源数据日与 `refreshed_at`。整批替换，一张表只保留当前发布结果；检查同批次和同数据日，不扫描 Daily 或静态明细。可读时再读取 `adm_uniseek_refresh_state`，观察是否有已确认但未发布的批次。
- **ADM 日聚合**：读取 `adm_entity_metrics_daily` 最新业务日的结果行数、`computed_at` 与完整性，并观察 `adm_aggregation_task` 最近更新的任务。处理方式是按业务日原子覆盖重算，其他历史日期保留，不等同于每次全库重建或对旧指标递增。最近任务可能是在回刷旧日期，因此任务日期、任务状态与最新发布数据日期分别展示。任务成功不替代 `is_complete`；任务失败时旧发布结果继续显示。
- **PostgreSQL 定时任务**：只读取当前数据库连接及当前账号可见、目标为本业务库的 `cron.job` 与最近可见运行记录。按 jobid 展示名称、真实周期、启停、最近状态和开始／结束时间，最多 100 个任务，超出明确提示。未识别的任务不猜测为全量。SQL 命令、连接端点、用户名和原始错误详情不发送到前端。
- **视频三维打标 TODO**：只说明是否歌曲、是否符合虚拟歌声口径、实际演唱语言三个独立维度，以及首批回填后按内容变更增量维护的规划。表尚未建立，不查询旧 `label_*` 字段冒充新流程进度。资料不足保留不确定，汉语包含普通话和方言，简繁字幕不改变演唱语种。
- **UP 主创作者识别 TODO**：依赖视频标签，按约定范围聚合有效投稿数和比例，结合最低样本量、待判定及人工修正；分母和阈值未冻结。表尚未建立，卡片保持 TODO，不以既有 `videos_filtered` 等字段伪造识别结果。

## 调度定义与线上观测

仓库定义的两个作业用于核对，不作为线上启用证据：

- `hantang-uniseek-search-refresh`，`*/10 * * * *`：调用 `adm_refresh_uniseek_videos`，有新的确认批次才整批发布。
- `hantang-adm-daily`，`*/5 * * * *`：调用 `adm_schedule_aggregation_tick`。过程内部在北京时间 09:00 后排入昨天并处理一个到期任务；成功日期不重复排入，亦可处理历史回刷／重试队列。

作业调度成功可能只是没有待处理数据的空跑，不能当成发布成功。发布结果存在也不能证明 CRON 正在运行。运行日志可能被清理；没有可见记录、没有权限或连接到了其他管理库时，只展示无法观测，不声称没有任务或任务从未运行。当前实现不跨数据库自动尝试额外凭据、不申请或改变权限。

本次有限只读核对发现：应用账号可读搜索结果表；日聚合、控制表和 CRON 清单缺少相应读取权限。页面仍展示可核实的发布数据，其他部分显示权限限制；数据库统计估算若可见，会明确标为全表估算，不冒充最新批次的精确行数。该核对是当时账号可见范围的样本，不是完整调度资产清单。

## API 与健康语义

`GET /admin/data/processing/{source}` 使用标准 ResponseDTO 信封，source 白名单为 `search`、`aggregation`、`scheduler`。其余（包括两个 TODO）返回 404，不访问数据库。三个来源独立请求和重试，离开页面取消浏览器请求。每来源缓存 60 秒并合并并发请求；数据库工作线程 2、队列 16，单条 SQL 只读且超时 2 秒，禁用本次 JIT。工作队列满返回 503，核心查询失败返回 500，不向前端泄露内部错误。

- 绿色：已观测的结果可用；调度清单需有可见成功记录才标为正常。
- 橙色：没有可见结果、结果不完整、等待发布／重试、停用、日志不可见或权限不足。权限不足不是业务失败，更不能当成空表。
- 红色：实际观测到最近任务失败或结果批次不一致；状态查询失败在前端单独标为「查询失败」，不冒充任务执行失败。
- 灰色：正在查询／处理，以及两个 TODO。

颜色、图标和文字沿用现有 `.ds-status-tag` 与 `--status-*` 语义变量。任务状态表读取失败时保留已读取的发布结果并补充说明；分别读取的数据可能跨发布提交，不用两个独立快照的批次差异制造错误告警。

## 后续 Java 与增量任务

接口将 `engine` 与 `mode` 分开。当前 SQL 卡片分别为 `full` 和 `by_day`；前端同时预留 `incremental` 和未知处理方式，不按调度引擎推断全量／增量。未来 Java 任务需新增实际只读适配器、注册任务及文案，提供真实最近执行状态、完成时间和处理数量；增量任务还需有持久游标／水位及积压口径，再接入相应监控。不在本次创建 Java 调度器或虚构任务进度。

验证覆盖权限隔离、缺表、缓存合并和重试、最近任务失败与旧结果保留、完整性、待发布批次、未知调度方式和日志缺失。SQL 回归提取生产 DAO 查询，在隔离 PostgreSQL 验证当前批次、最新业务日、历史回刷顺序、CRON 可见范围和实际只读权限边界。

手动验收入口 `/admin/data/processing`；MOCK 状态明确标注为示例，网络失败不回退为 MOCK。相关业务定义见[视频三维打标与创作者识别待办](../todo/uniseek-song-classification.md)。
