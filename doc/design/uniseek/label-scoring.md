# UniSeek：1000条结果对照评分

更新：2026-11-20。已实现本地确定性评分、网页任务结束后自动评分、已有结果单独重评分和离线入口。只使用既有1000条人工参考答案与保存的模型预测，不调用模型，不写业务数据库。

## 评分口径

参考答案固定默认使用`script/uniseek/reference_answers.reviewed-final.json`；只接受全部条目均为“已确认”的完整参考文件。按aid对齐，不依赖预测条目顺序；已有预测的原始input须与参考答案一致。重复/额外aid、范围不符或输入版本不一致会使本次评分失败，保留打标文件，不输出误导性分数。

本轮规则版本为`song-eligibility-v1`，每条可判分的参考答案最多得1分：

- 参考答案为歌曲且虚拟歌手为“是”或“混合”：预测也必须是歌曲，且虚拟歌手为“是”或“混合”。
- 参考答案为非歌曲：预测只须为非歌曲，声源及语言不影响得分。
- 参考答案为歌曲且非虚拟歌手：预测也须为歌曲且非虚拟歌手。

参考答案无法明确归入三类时，标记无法判分，不进入评分分母；非歌曲即使声源不确定仍可判分。预测在必需字段上不确定时不得分。可判分参考答案缺失预测（包括执行失败）时计入分母、得0分并单列。语言完全不参与本轮得分。混合只在评分时归入虚拟歌手，不改写原始标签、现有人工复核筛选或生产业务口径。

得分率为`correct_count / scorable_count`；分母为0时为null，界面显示“—”。错误数包含缺失预测。逐条报告保留原始参考/预测标签、归类、核对结论和分值；无法判分的分值为null。

本次按用户指定核对全部1000条，包括提示词中的6条示例，报告单列示例数量，并明确不是独立盲测；不沿用先前“排除示例后做独立盲测”的评分范围。

## 自动评分与重新评分

Qwen任务结果落盘后，Controller调用独立的`VideoLabelScorer`；打标耗时与评分分开。评分期间显示“正在核对评分”，完成后显示总分、三类成绩、无法判分数量及可展开的未得分/无法判分/全部明细，提供评分JSON下载。参考答案或评分规则有更新时，可点击“重新评分（不调用Qwen）”，只核对当前保存结果。

每个运行目录增加`predictions.score.json`及不含逐条记录的`predictions.score-summary.json`。报告记录规则版本、评分时间、参考答案及预测文件的SHA-256；状态轮询仅读取小摘要，逐条明细按需读取。评分失败不改变打标任务的成功/失败状态，不覆盖人工参考答案或预测文件；刷新和重启恢复已保存评分，评分过程中重启则提示重新评分，不自动发起推理。

接口：`POST /admin/content/video-analysis/score`仅重新评分，`GET /admin/content/video-analysis/score/details`读取完整明细，`GET /admin/content/video-analysis/score`下载JSON；沿用本机连接限制。页面加载只读，不触发打标或评分。

## 离线入口

同一Java评分器提供main入口：

```sh
java -cp target/hantang-web-backend-1.0-SNAPSHOT.jar \
  com.hantang.web.service.labeling.VideoLabelScorer \
  script/uniseek/runs/web-419ec03b-65e9-4a64-a01d-46bab4ae2642/predictions.json \
  script/uniseek/reference_answers.reviewed-final.json \
  target/uniseek/scores/web-419ec03b.score.json
```

后两个参数可省略；默认参考答案如上，默认输出为`target/uniseek/scores/score-<UUID>.json`。输出必须是新文件，不覆盖输入或已有报告。该入口不加载LLM私密配置，不调用模型，不改写历史归档目录。
