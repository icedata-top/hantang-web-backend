# 视频详情与创作者详情 URL

日期：2026-10-29。状态：视频详情已接入基本信息与最新日快照接口，支持 BV 入口规范化与两种业务结果页；创作者详情保留空白占位。本设计沿用当前前端的 `/videos`、`/producers` 分类路径。

## 视频详情

网页路径：`/videos/:aid`。

世末歌者实例：`/videos/6009789`。

- `aid` 为视频的正整数 AV 号，对应 `hantang_dynamic.processed_videos.aid`；路径中只放数字，不带 `av` 前缀。
- 标题、投稿时间、封面、简介和上传者等静态信息统一读取 `processed_videos`。如无必要，不得使用 `video_static`，也不得默认回退。
- `/videos` 保留为视频列表入口；`/videos/:aid` 表示一个视频投稿，不表示多个投稿合并后的音乐作品。
- 默认生成的站内链接统一使用 aid。前端也接受 `/videos/:bvid`，格式为 `^BV1[1-9A-HJ-NP-Za-km-z]{9}$`，区分大小写；AV 入口格式为 `^[1-9]\d*$`，不接受 `av` 前缀。
- BV 入口复用后端 `BilibiliUtils` 的 51 位算法，在前端用 BigInt 本地转换成 aid，再以 `replace` 跳到纯数字 URL，保留查询参数和锚点。转换入口不发视频查询请求，不调用哔哩哔哩 API；只有跳转后的数字页面查询本站接口。API 层全部使用 aid，不使用 HTTP 301/308。

## 创作者详情

网页路径：`/producers/:userId`。

COPY 实例：`/producers/396194`。

- `userId` 为用户的正整数 ID，对应 `hantang_dynamic.discovered_users.user_id`。
- 账号名称、头像、签名、粉丝数及认证信息来自 `discovered_users`。
- `/producers` 保留为创作者列表入口，与现有导航中的分类路径一致。
- 当前 URL 标识的是创作者账号。由 `processed_videos.user_id` 关联的视频只能认定为该账号的上传作品，不能据此声称覆盖全部参与创作的作品或角色；后续协作者与角色关系另行定义。

## 跳转与 URL 规则

- 视频详情中的上传者链接：使用视频记录的 `user_id`，例如从 `/videos/6009789` 跳到 `/producers/396194`。
- 创作者详情中的视频链接：使用对应视频的 `aid`，例如跳到 `/videos/6009789`。
- 路径只使用稳定 ID，不放标题或用户名；名称变化不影响已有链接。
- 默认 URL 使用小写分类路径，不带末尾斜杠，不添加 `.html`，也不使用 hash 路由。
- 使用站点相对路径，部署到哪个域名就沿用哪个域名；本文不假定生产域名。这两项是网页 URL，不是后端 API 地址。
- 视频详情区分两种业务结果页：ID 不符合 AV/BV 格式时显示「你输入的ID不合法」，不发请求；格式合法但基本信息接口返回 404 时显示「你输入的ID，在哔哩哔哩不存在或者冰数据未收录」。格式合法但转换为 0 或超出本站 API 正 64 位 aid 范围的输入，同样归入未找到，不误报格式错误。格式合法不等于哔哩哔哩存在，也不等于冰数据已收录；不调用哔哩哔哩 API 时不区分后两者。
- 网络或服务端错误仍显示加载失败与重试，不误判为视频不存在；基本信息存在但日快照缺失时保留视频信息。不从 `video_static` 补造详情。不带 ID 的 `/videos`、`/producers` 是独立列表入口。创作者占位页仍只校验不带前导零的正整数 ID，不检查记录是否存在。
- 视频存在但账号资料缺失时，仍保留视频内容；若有有效 `user_id`，可显示该 ID，账号详情页按资料缺失状态处理。
- 日期筛选、标签页等状态若后续需要可分享，再设计查询参数；它们不改变对象的路径 ID。本次不预设尚未确定的页面模块。

## 当前实施状态

`frontend/src/App.jsx` 已注册 `videos/:aid`、`producers/:userId`，分别使用 `pages/video/VideoDetail.jsx`、`pages/producer/ProducerDetail.jsx`。两个页面保留公共导航；创作者详情仍为空白占位，视频详情已通过两个独立请求读取基本信息和最新日快照。接口契约见[视频详情 API](../../frontend/src/services/Video/video.md)。

视频页的面包屑、标题和简要信息栏直接位于 Canvas 上。桌面端左侧封面与右侧创作者/数据两张卡片（含间隙）等高；右侧宽度为 320px，收紧卡片内外留白，让封面更舒展。创作者 ID 与橙色认证头衔并排，个人简介只保留一行，超出以 `...` 省略，悬停或键盘聚焦显示完整内容。数据卡片保留“最新数据”标题，去掉副说明；七项指标沿用原有纵向间距，数值右对齐，卡片右下角显示“统计于 yyyy-MM-dd 凌晨”。简介和标签位于整体下方，暂不提供趋势图。移动端使用单列。

封面悬停时显示深色蒙层，中央左右排列下载、观看两组操作，各自为上图标、下文字且居中对齐；键盘聚焦同样可用，触屏设备常显操作。标题、简介、标签以纯文本方式将 `&amp;` 替换为 `&`；投稿时间后按北京时间日期计算“XXX天之前”，宽开口标点开头的标题只对首行做视觉悬挂，不裁剪原文。

`frontend/src/routes/menuPaths.js` 已为两类详情路径选中对应的「歌曲」「创作者」导航项。`/videos`、`/producers` 仍保留原有的列表待开发入口。

前端使用 `BrowserRouter`；仓库 Caddy 配置已有回退到 `index.html` 的规则，无需为这两个路径增加专门的服务器转发。发布后仍需在部署环境验证直接打开和刷新详情链接；本次仅改动本地项目，不代表页面已上线。

数据字段、时间口径和 NULL 语义见[视频与创作者表文档](../../sql/video_creator_reference.md)，实例见[世末歌者与 COPY](../../sql/examples/video_creator_sample.md)。其他列表、筛选与页面内容的早期讨论见[导航与发现草稿](navigation-and-discovery-draft.md)。
